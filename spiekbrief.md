# Spiekbrief Git en Github

## 1. Clone, commit, push en pull
Met Clone kopieer je een project van GitHub naar je computer.
Met Commit sla je wijzigingen lokaal op en met Push upload je ze naar GitHub.
Met Pull haal je de nieuwste wijzigingen van GitHub op.

## 2. Een goed commitbericht

Goed voorbeeld: "Loginfout opgelost"
Slecht voorbeeld: "Dingen aangepast"

Het goede bericht is beter omdat het duidelijk vertelt wat er veranderd is, terwijl het slechte bericht te vaag is.

## 3. Gitignore

Gitignore zorgt ervoor dat Git bepaalde bestanden negeert, zoals tijdelijke bestanden en logbestanden. Dit is handig omdat onnodige bestanden dan
niet op GitHub terechtkomen.

## 4. Pull

Met Pull heb ik de nieuwste wijzigingen van GitHub naar mijn computer gehaald. Aan het begin van elke les doe ik eerst een Pull zodat ik altijd met
de nieuwste versie werk.

## 5. Terugdraaien

Met Git kun je een foute commit terugdraaien. De foute commit blijft in de geschiedenis staan omdat Git alle wijzigingen bijhoudt.

## 6. Branches en pull requests
Een branch is een aparte versie van je project waarin je wijzigingen kunt maken. Main blijft altijd de werkende versie zodat er geen fouten in komen.
Een pull request is een verzoek om je wijzigingen samen te voegen met main.

## 7. Mijn conflict

Ik heb dezelfde titel op GitHub en op mijn laptop anders aangepast. Daardoor ontstond er een merge conflict. Ik heb gekozen voor één duidelijke titel omdat dit overzichtelijker is.
